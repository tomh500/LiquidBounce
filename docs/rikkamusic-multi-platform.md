# RikkaMusic 多平台实验

分支：`codex/rikkamusic-multi-platform`。网易云仍为默认搜索来源。

## 使用

- 搜索歌曲后选择网易云、QQ 音乐或混合搜索。歌单和歌手搜索仍使用网易云。
- 点击单曲旁的“＋收集”或“收集本页到混合曲库”。网易云已打开的歌单也可以整页收集。
- 左侧“混合曲库”支持输入 QQ／网易云完整歌单链接或数字 ID，批量导入可访问的歌单。
- 混合曲库使用同一个播放队列，每首歌显示实际来源。按平台和平台歌曲 ID 去重，不自动合并翻唱、现场版或同名歌曲。
- 曲库保存为游戏目录中的 `LiquidBounce/rikkamusic-library.json`；仅保存歌曲元数据，不修改远端账号收藏。
- 右上角“QQ 登录”或混合曲库中的“QQ / 微信扫码登录”可获取二维码。手机确认后交换 QQ 音乐播放凭据并保存到本机；下次启动自动读取。高级入口仍支持手动导入自己的 Cookie。

## 当前边界

- QQ 登录凭据保存为游戏目录中的 `LiquidBounce/rikkamusic-qq-account.json`，该文件及临时文件已加入 Git 忽略。状态接口不返回 Cookie/token；退出 QQ 登录删除本机凭据。QQ 与网易云账号相互独立。
- QQ 使用标准 MP3 音质，播放权限由平台决定。没有可播放地址的 QQ 曲目会显示原因，并继续尝试队列中的下一首；队列末尾失败则停止，避免无限重试。
- 支持跨平台曲目连续排队和切换；尚未实现同一录音的跨平台匹配、进度续播、交叉淡化或音频级无间隙衔接。
- 尚未接入 QQ 账号歌单自动同步和歌词。扫码登录支持 QQ、微信两种方式；凭据过期时需要重新扫码。
- 完整歌单链接和数字 ID 可导入，分享短链接暂不支持。实验版曲库上限为 10000 首；无法完整获取的歌单不会作为成功导入。
- 搜索结果使用服务端快照播放，避免再次搜索后结果排序变化导致播错歌曲。快照过期后需刷新对应列表。

## QQ / 微信扫码实现

- 每次扫码都有独立 HTTP 客户端和请求代次；切换方式、关闭窗口或退出登录会取消旧请求，迟到的授权结果不能恢复已退出的账号。
- 二维码只保存在内存，通过带版本的本地接口读取，并返回 `Cache-Control: no-store`。
- QQ 使用腾讯扫码确认和 QQ Connect 授权码交换；微信使用 QQ 音乐的微信登录应用及音乐登录交换接口。
- 只持久化音乐服务需要的登录 Cookie、登录方式、昵称和已知过期时间；不保存 QQ 通用会话 Cookie、二维码签名或 OAuth 临时授权码。
- 完整授权仍需要用户在手机端确认。单元测试使用虚构凭据，不需要账号；可选在线测试仅验证二维码图片与等待扫码状态。
- 实际 QQ 扫码确认后曾返回 `302 graph.qq.com/oauth2.0/show`，而不是携带音乐授权码的回调。现在将其识别为 `consent_required`，停止轮询、清除二维码并显示官网登录/授权入口；不会把它标为登录成功或保存空凭据。用户需先在官网用同一 QQ 完成登录/授权，再回到客户端扫码；这一恢复路径仍待真实账号验证。
- 回调只接受 QQ 音乐固定域名与路径，并核对 state。兼容默认端口和 HTTP 回调字符串，但不访问该 HTTP 地址；错误诊断仅包含预设目标分类和数字错误码，不返回完整跳转地址。
- 授权页处理补丁验证：编译、前端检查、68 个语言 JSON 解析通过；22 项测试通过且无跳过，包含真实二维码连通性与授权页状态清理测试。
